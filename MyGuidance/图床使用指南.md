## 一、先理解工作方式

这是一套“本地处理 + 静态发布”的个人图床，不是公开上传网站。

```text
工作区内的原图
  → 本地导入与 WebP 转换
  → image-host/public/images/（哈希文件名）
  → 本地检查与备份
  → 明确确认后部署独立 Cloudflare Worker
  → 测试实际图片链接
  → 最后才在博客中引用
```

- 博客与图床使用不同的部署配置。不要用博客的 `pnpm deploy` 代替图床发布。
- 不需要启动上传服务器；读者访问的是静态图片。
- 原图不会被脚本改写。图床副本是持久文件，不能当作临时输出删除。
- 所有命令从博客根目录执行：`/home/mofengwei/MyBlog/Firefly`。
- Windows 下在对应 WSL 工作区的 VS Code 终端操作；不要直接传入 `C:\...` 路径。
- 示例中包含“实际域名”“path/to/”的值必须替换，不能原样执行。

## 二、操作边界：什么会上传？

| 命令 | 作用 | 影响云端吗？ |
|---|---|---|
| `help` | 查看命令 | 否 |
| `batch 目录` | 递归扫描并预览 | 否；不导入图片 |
| `add 文件` | 导入指定图片并写来源清单 | 否 |
| `batch 目录 --confirm-import` | 按当前目录内容批量导入 | 否 |
| `check` | 检查图片库及已有图片基线 | 否 |
| `links 域名` | 更新本地 Markdown 清单 | 否；不绑定域名 |
| `backup` | 复制本地图床输出与状态 | 否 |
| `publish-check` | 发布保护预检 | 否；不核实云端账号 |
| `dry-run` | 使用 Wrangler 验证发布配置和资源 | 不部署；不创建发布基线 |
| `publish 域名 --confirm-deploy ...` | 调用 Wrangler 部署 | **是** |

命令会临时创建操作锁，正常结束后清理。预览不写图片或来源清单，但不应把整套命令理解成完全不触碰本地文件系统。

## 三、首次本地使用：一步一步来

### 第 1 步：确认目录与工具

```bash
pwd
node image-host/image-host.mjs help
```

本项目复用现有 `sharp` 与 `wrangler` 依赖，无需为图床单独安装另一套包管理器。
如果迁移到新电脑后提示依赖缺失，先按博客项目规范恢复 `pnpm` 依赖，不要随意用 npm 改写锁文件。

### 第 2 步：选择原图与压缩模式

先把原图放在工作区内、`image-host/` 外。建议按文章分目录；路径有空格时用引号包住。
不要把私密照片、账号截图、定位信息或不允许公开传播的图片作为测试素材。

| 图片类型 | 推荐模式 | 行为 |
|---|---|---|
| 论文图表、代码截图、流程图 | `--lossless` | 不主动缩放，WebP 无损编码 |
| 普通照片、装饰图片 | 默认 | 最长边 2400，WebP 质量参数 85 |

两种模式都会按 EXIF 方向旋转，默认不保留原始元数据。移除元数据不代表截图中可见的隐私已被脱敏。
无损转换不能恢复原图既有损失，也不保证文件一定更小。完全透明区域的隐藏 RGB 可能被 WebP 编码器归一化；本次桌面宠物封面有此情况，可见像素及透明度保持一致。
当前支持静态 PNG/JPEG/WebP/AVIF，不支持动画或 SVG；不跟随符号链接。

### 第 3 步：导入单张图片

以下是现有图表的本地导入示例，重复导入会按输出内容去重：

```bash
node image-host/image-host.mjs add src/content/posts/images/detr/detr-overview.png --lossless
```

成功后会产生或复用：

- `image-host/public/images/<内容哈希>.webp`
- `image-host/manifest.json` 中的来源记录

不要手工将哈希文件名改成中文或文章标题。可读名称保留在清单中；哈希名称用来保障链接与长缓存的一致性。

### 第 4 步：批量导入先预览，再确认

```bash
# 先看有哪些文件会处理
node image-host/image-host.mjs batch src/content/posts/images/detr --lossless
```

检查“可处理”“跳过”列表，确认没有混入不应公开的图片，再运行：

```bash
node image-host/image-host.mjs batch src/content/posts/images/detr --lossless --confirm-import
```

注意：

1. 每次确认都会重新扫描，不是锁定上次预览的文件列表；两次操作之间不要修改目录。
2. 不支持格式和损坏图片会跳过并说明原因；发现符号链接会中止扫描。
3. 不要选择整个博客目录，避免扫描依赖、备份和无关素材。
4. 批处理不是全有或全无的事务；失败前成功的条目会保留，修复问题后可重跑。
5. 编码模式或 Sharp 版本变化可能产生不同哈希，不会自动清理旧输出。

### 第 5 步：检查与生成可读清单

```bash
node image-host/image-host.mjs check
node image-host/image-host.mjs links https://img.2298321.xyz
```

打开 `image-host/links.md`，确认原图名称、尺寸、压缩前后大小、比例与 Markdown 链接。
此处使用已验证的自定义图片域名。`links` 只生成链接，不主动联网验证；当前已有 14 张图片通过上线验证，未来新增图片仍需先发布再验证。

> 编辑器或受限预览环境可能无法加载远程图片，可在浏览器中打开完整链接，或直接打开 `image-host/public/images/` 内的 WebP。不要把预览加载失败直接等同于图床部署失败。

### 第 6 步：创建备份

```bash
node image-host/image-host.mjs backup
```

备份位于 `image-host/.backups/<时间-随机标识>/`，复制完整 `public/`、已有来源清单、配置及已有发布基线，并校验复制内容。

- 不包含原图，原图另行保存。
- 不上传云端，也未纳入 Git。
- 同磁盘备份不能防止磁盘损坏；应另行复制到自己控制的离线盘或备份位置。
- 没有自动清理功能，长期使用要关注磁盘占用。

## 四、首次上线流程（本次已完成，保留作为新环境参考）

本节用于理解首次部署；当前图床已经上线，不要重复初始化或删除基线。以下核对表也适用于今后另建全新图床。

### 上线前核对表

- [ ] 确认登录自己的 Cloudflare 账号，并核实 Workers 保持 Free。
- [ ] 确认目标 Worker 名 `mfwblog-images` 未被其他服务使用。
- [ ] 确认图片可以公开，原图与本地输出都有备份。
- [ ] 核实实际 workers.dev 测试域名；不要将示例占位符当作域名。
- [ ] 检查没有计划外的付费绑定或在线转换服务。
- [ ] 明确同意执行这一次云端部署。

首次需要登录时，在本机按 Wrangler 的授权流程完成。不要在聊天、Markdown、Git 或脚本中保存 Token。
脚本不能自动核实账号套餐；本地预检通过不等于账号和费用检查通过。

### 本地预检

```bash
node image-host/image-host.mjs dry-run
node image-host/image-host.mjs publish-check --first-deploy
```

两个命令都不上传。`dry-run` 检查 Wrangler 配置与资源，`publish-check` 检查本地发布保护；都不能替代真实账号套餐和线上链接验收。`--first-deploy` 仅供真正首次部署，不是绕过旧图保护的开关。

本机 Wrangler 4.122.0 曾在显示结束提示后不退出；已通过子进程参数跳过横幅附带的后台版本检查，同时使用非交互模式及关闭遥测，验证正常退出。以后优先使用脚本的 `dry-run`，不要只凭 CLI 打印 `exiting now` 判断成功；必须检查退出码。该处理不修改全局代理或环境，也不关闭实际配置/权限检查。

### 真正首次部署

只有核对表完成后，才将下方域名替换为真实测试域名并执行：

```bash
node image-host/image-host.mjs publish https://实际测试域名 --confirm-deploy --first-deploy
```

流程：检查 → 旧图保护 → 本地备份 → 记录未决部署 → Wrangler 发布 → 成功后保存基线 → 生成链接。
域名参数只影响链接文本，不会自动添加 DNS 记录或绑定域名。

### 部署后验收

1. 使用真实链接直接打开两张测试图片，确认 HTTPS 正常、内容正确。
2. 验证不存在的图片地址返回失败，而不是博客首页。
3. 分别在大陆和海外网络测试加载，不能只凭本地或代理网络成功下结论。
4. 再决定是否绑定 `img.2298321.xyz`；绑定前检查已有 DNS，避免覆盖其他服务。
5. 自定义域名生效后重新生成清单。
6. 最后只试改一篇文章，分别检查正文与封面；保留原相对路径及原图作为回滚依据。

当前图床已上线，但文章迁移仍属于下一阶段，当前脚本不会改文章。涉及 Astro 渲染和图片处理时，按项目规则运行 `pnpm check`、`pnpm type-check`、`pnpm build`，并检查实际页面。现有 `cloudflare-binding` 图片链路也需单独核实，不能仅凭直链成功认定接入完成。

## 五、上线后的日常更新（当前使用流程）

```text
整理新增原图 → 批量预览 → 确认导入 → check → publish-check
→ 明确发布 → 验证实际链接 → 复制 Markdown 到文章 → 验证博客
```

已经成功部署后，预检和发布不再需要首次标记：

```bash
node image-host/image-host.mjs check
node image-host/image-host.mjs publish-check
node image-host/image-host.mjs publish https://img.2298321.xyz --confirm-deploy
```

发布是发布整个当前静态图集，不是仅上传“本次新加的那几张”。需要保留旧图，不能为节省本地空间删掉已发布输出。
默认不提供强制删除旧图的命令。如果必须撤下涉及隐私的图片，应作为单独的删除与缓存清理任务处理，不能只删除本地文件就认为线上已不可访问。

## 六、异常处理：先辨认，不要绕过保护

| 提示或现象 | 原因与下一步 |
|---|---|
| 没有成功发布基线 | 当前可能尚未部署；确认是否真正首次上线。若以前部署过，不要直接添加首次标记，先恢复基线。 |
| 误删保护：已发布图片缺失或改变 | 从完整备份恢复相应文件，再运行检查；不要编辑哈希名称或删除基线。 |
| 内容哈希不匹配 | 输出文件被修改或损坏；恢复正确副本。重新导入只有输出内容完全相同时才会复用原链接。 |
| 未决部署 `publish-pending.json` | CLI 失败或中断，结果不明确；先核对 Cloudflare 部署历史和本地未决记录，确认状态后人工恢复。 |
| 操作锁存在 | 可能还有另一个命令在运行；先确认进程状态。只有确定是异常遗留的空锁目录才移除。 |
| 目录中有跳过项 | 查看具体原因；不支持格式需预先转换，损坏图片需更换原文件。 |
| 生成的链接打不开 | 可能尚未部署、域名未绑定、DNS/TLS 未生效或网络不可达；`links` 本身不验证这些条件。 |
| 本地清单和备份没有出现在图床 | 正常，只有 `public/` 会上传。 |

未决部署恢复原则：

- 确认云端未发生部署：保留原成功基线，归档未决记录后再恢复操作。
- 确认云端已成功部署：根据该次未决记录中的目标与资产清单修复基线，再恢复操作。
- 无法确认：停止，不删除状态文件，不重复发布。

这些是人工核对步骤，不提供自动“清空状态”命令。当前工具也不是云端资产审计器，无法检测别人从控制台发布的变化。

## 七、哪些文件应该保留？

| 路径 | 用途 | 保存建议 |
|---|---|---|
| 原图目录 | 原始素材 | 独立备份，不因图床转换成功就删除 |
| `public/images/` | 实际发布图片 | 持久保存，适合私有版本管理/备份 |
| `manifest.json` | 来源、尺寸和压缩记录 | 建议保存；路径可能含隐私 |
| `published.json` | 上次成功发布的图片基线 | 首次成功上线后才生成，必须保存 |
| `publish-pending.json` | 未决部署状态 | 异常时保留调查，不能随手删 |
| `.backups/` | 本地快照 | 定期复制到另一存储位置；Git 忽略 |
| `links.md` | 可再生 Markdown 清单 | 可重新生成；Git 忽略 |
| `wrangler.jsonc`、脚本、测试和说明 | 配置与工具 | 纳入版本管理，不写入密钥 |

robots 与 noindex 不提供鉴权；任何知道图片链接的人都能访问。当前没有防盗链，文件名哈希也不是密码。

## 八、免费边界与文档维护

当前按 Workers Static Assets 设计：无业务 Worker 脚本，无 R2/KV/D1，无在线图片转换。
2026-09-26 核实的官方限制为：Free 每个 Worker 版本最多 20,000 个静态文件，单文件最多 25 MiB；静态资源请求免费，资源存储不另收费。本脚本为两个辅助文件预留位置，最多接收 19,998 张图片。

免费政策可能变化，不承诺永久免费，也不保证大陆访问稳定；现有域名续费不属于图床免费范围。上线前应重新核实账号与官方政策。

官方参考：

- https://developers.cloudflare.com/workers/static-assets/billing-and-limitations/
- https://developers.cloudflare.com/workers/platform/limits/
- https://developers.cloudflare.com/workers/static-assets/get-started/

本项目文档分工：

- 本指南：面向日常使用，按步骤操作。
- `image-host/README.md`：命令和技术边界速查。
- `image-host/PROGRESS.md`：实际完成状态、验证记录和下一阶段待办。
- `image-host/links.md`：由脚本生成，不手工维护通用教程。

每推进一个阶段，同步更新进度记录；只有实际部署或绑定成功并验证后，才能把“待部署”“候选域名”改成“已上线”“正式域名”。不要在记录中保存账号密钥。
